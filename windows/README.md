# Keyboop для Windows

> **wrong layout? keyboop.** Теперь и на Windows.

Переключатель раскладки, который чинит кракозябры (`ghbdtn` → `привет`) прямо во время
набора и **не трогает буфер обмена**: исправленный текст печатается напрямую через
`SendInput`, как будто его набрали вы.

Это порт мак-версии. Детектор раскладки, словари, триграммы и все правила, выверенные
отзывами, общие: Rust-ядро [`core/`](core) — построчный перенос `Sources/Keyboop/*.swift`
(`LayoutDetector`, `Keymap`, `KeystrokeBuffer`, `Engine`, `UndoLearner`, `TypoFix`…), а
списки слов и словари берутся из тех же файлов, что у мак-версии. Правка в Swift-списке
попадает в Windows-сборку автоматически.

## Что умеет

| | |
|---|---|
| Авто-переключение на границе слова | пробел / Enter (Tab — в настройках) |
| Правка на лету | посреди слова, как только сочетание букв невозможно в текущем языке |
| Enter-pre | слово чинится **до** того, как Enter отправит сообщение в чате |
| Ручной хоткей (**Pause**) | последнее слово туда-обратно; если буфер пуст — выделенный текст |
| Регистр выделенного (**Alt+Pause**) | всё в ЗАГЛАВНЫЕ ↔ строчные |
| Сниппеты | `snippets.json`, раскладка и регистр набора не важны |
| Обучение на отмене | трижды вернули слово — Keyboop предложит больше его не трогать |
| Исключения | слова и программы: «обычно», «мягко», «не трогать», жёсткая раскладка |
| Опечатки, две заглавные, след Caps Lock | выключены по умолчанию, как на Маке |
| Пауза «не мешать» | 15 минут … 5 часов из меню |
| Значок в трее | показывает текущую раскладку (EN/RU), оранжевый — авто выключено или пауза |

По умолчанию Keyboop не вмешивается в терминалы и программы с «голыми» горячими клавишами
(Premiere, DaVinci Resolve, Blender, Ableton…), а в редакторах кода (VS Code, JetBrains,
Visual Studio…) работает мягко. Всё это меняется в меню трея: пункт «Программа: …»
относится к окну, которое было активно перед открытием меню.

## Установка и запуск

Нужна Windows 10 1607+ (или Windows 11), x64. Установки нет: `keyboop.exe` — один файл,
словари вшиты внутрь. Положите его куда угодно и запустите; для автозапуска включите в
меню трея «Запускать вместе с Windows».

Настройки и данные: `%APPDATA%\Keyboop\`

| файл | что внутри |
|---|---|
| `settings.json` | все настройки, включая хоткеи |
| `exceptions.json` | слова «не переключать» / «всегда переключать», выученные, режимы программ |
| `snippets.json` | `[{"trigger": "mail", "text": "me@example.com"}]` |
| `state.json` | служебное: счётчики, обучение на отмене |
| `keyboop.log` | диагностика — **без** содержимого набранного, только длины и классы |

Файлы открываются Блокнотом из меню трея и перечитываются сами после сохранения. Если в
JSON ошибка, Keyboop его не перезапишет: работает на значениях по умолчанию и скажет об этом.

### Хоткеи

Формат в `settings.json`: `"Pause"`, `"Ctrl+Shift+K"`, `"Alt+Pause"`, `"F12"`, `"CapsLock"`
или тап одиночного модификатора: `"RCtrl"`, `"RShift"`, `"LAlt"`, `"RAlt"`, `"LWin"`
(нажал и отпустил, ничего между). Пустая строка выключает хоткей.

- `hotkey_convert` — переключить последнее слово или выделенное (по умолчанию `Pause`);
- `hotkey_case` — регистр выделенного (по умолчанию `Alt+Pause`);
- `hotkey_switch_layout` — только сменить раскладку, как 🌐 на Маке (например, `CapsLock`).

⚠️ Alt+Shift по умолчанию занят в Windows переключением языка, поэтому мак-овский ⌥⇧ здесь
заменён на Pause — привычный хоткей для тех, кто переходит с Punto Switcher.

## Сборка

```bash
# на Windows (MSVC)
cargo build --release
# или кросс-сборка из Linux/macOS
rustup target add x86_64-pc-windows-gnu      # + mingw-w64
cargo build --release --target x86_64-pc-windows-gnu

cargo test          # тесты ядра и переносимых частей — на любой ОС
```

Сборка читает `../Sources/Keyboop/ExtraWords.swift` и `../Sources/Keyboop/Resources/*.json`,
поэтому нужен весь репозиторий, а не только эта папка.

## Как это устроено

- `core/` — всё, что не зависит от ОС. Системное спрятано за трейтом `Platform`, поэтому
  движок целиком проверяется тестами на эмуляторе текстового поля (`engine.rs`, внизу).
- `app/src/win/hook.rs` — низкоуровневые хуки клавиатуры и мыши и **вся** печать замен в
  одном потоке. Вокруг нашей синтетики стоит «забор»: настоящие нажатия, успевшие попасть
  в очередь раньше пачки замены, придерживаются и переигрываются после неё, поэтому
  быстрый набор не перемешивается с заменой.
- `app/src/win/layouts.rs` — раскладки (HKL) и живая таблица символов из `ToUnicodeEx`
  (аналог `DynamicKeymap`): «Русская», «Русская (машинопись)» и любая латинская
  конвертируются по своим настоящим клавишам.
- `app/src/win/clipboard.rs` — чтение выделенного через Ctrl+C **только** по явному хоткею
  на выделении; буфер обмена затем восстанавливается как был (все форматы), если его никто
  не успел изменить.

## Чего пока нет по сравнению с Маком

- **Голосового ввода** (Whisper/Parakeet) и **перевода выделенного** (Apple Translation) —
  на Маке они завязаны на системные фреймворки. Whisper переносится (whisper.cpp работает и
  на Windows), это следующий шаг.
- Окна настроек: вместо него меню в трее и JSON-файлы.
- Автообновления (Sparkle): новую версию нужно скачать вручную.
- Мёртвые клавиши (US-International) и IME: буфер набора их не видит.
- В программах, запущенных от администратора, Keyboop молчит — Windows не пускает туда
  синтетический ввод от обычного процесса (запустите Keyboop от администратора, если нужно).
